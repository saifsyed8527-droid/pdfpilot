# Image-to-PDF orientation and batch export — 3 November 2026

JPG to PDF previously displayed browser-oriented phone photos but embedded the raw JPEG orientation, so the preview and PDF could disagree. The converter now combines all eight EXIF rotation/mirroring values with each user-selected clockwise rotation using native PDF transforms. Original JPEG streams are unchanged; PNG transparency remains. Fit/A4/Letter, Auto/Portrait/Landscape, margins, file order, sorting, drag/keyboard rearrangement and merged or separate ZIP output keep the existing flow. The preview now uses the same placement calculation as export, including margins and extreme aspect ratios. A result opens at the top of the page on mobile, with an additional Back to images action.

The shared scanner exporter receives the same orientation and cancellation fixes. Both tools validate actual image headers and dimensions before preview, report rejected images without removing valid selections, and run conversion in a dedicated, terminable browser worker. PNG checksums are checked; animated PNG is rejected. Unicode ZIP names retain combining marks and avoid case-insensitive collisions. Inputs are read sequentially and decoded PNG memory is released after embedding. Cancellation or timeout terminates the worker and cannot publish stale output; a fresh retry uses the existing inputs.

Limits: 30 images, 100MiB and 40 megapixels per image, 16,384 pixels per side, 200MiB and 100 megapixels combined, and 200MiB output. Export timeout is 180 seconds. Fit maps 96 image pixels to one inch. Page orientation changes the paper; image rotation remains the explicit per-image action. No image resampling, target byte size, OCR, remote hosting or phone-to-computer transfer was added. Some color profiles and unusual image/reader combinations remain unverified. Camera hardware compatibility was not re-certified by this change.
