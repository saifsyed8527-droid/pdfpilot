# PDF Forms export verification — 29 October 2026

New fields are created before Fill values are applied, so values typed into a newly built form survive download. Clearing text, checkbox, radio, dropdown and list selections now clears the saved value. Multi-select values are arrays, preserving option labels containing commas. Read-only values are preserved and field errors stop export instead of producing a false success.

Widgets use the visible CropBox and native 0/90/180/270-degree rotation. Field dimensions include borders correctly. Imported widgets retain their content rotation, font size, colors and maximum text length in the preview. New multiline fields use textareas, labels identify the controls, and optional field indicators actually display. Mobile preview fits the available width; loading tasks are destroyed on replacement/unmount, and stale loads or cancelled exports cannot publish results.

Hindi form values and options use embedded fonts and remain real interactive AcroForm fields. A field appearance uses a single font, so unsupported glyph combinations fail with a field-specific error. XFA is rejected before pdf-lib can delete its form definition. Signature fields are unsigned placeholders; certificate signing is not implemented here.

Native text editing reuses PDF Editor's source-text removal and font writer. Bold, underline, color, size, alignment and deletion count as edits even when the words do not change. Complex source text uses a disclosed page-image fallback, preserving interactive widgets and untouched pages. This is not secure redaction. Indic pre-base vowel ordering in extracted replacement page text can still differ between readers (observed with हिन्दी in pypdf/PDFium); the visual text and the interactive field's stored Unicode value remain intact. Complete script/reader compatibility is not claimed.
