# Search intent and competitor evidence

Reviewed on 2026-09-29. SEMrush ranking URLs/positions are retained per observation in the existing reports. A competitor URL is evidence of a competing result format; it does not prove language, current Google rank, user intent on its own, or PDFPilot capability. The web checks below are primary-page samples, not a geolocated Brazilian Google top-ten ranking capture.

| Query family | Observed result format | PDFPilot ownership decision | What must be true |
|---|---|---|---|
| juntar / unificar / mesclar PDF | Upload-first merge tools, short steps and related conversions | One `/pt-br/juntar-pdf` owner | Merge and download actual pages; synonyms belong on the same page |
| converter PDF em Word | Dedicated conversion tool plus product instructions explaining editable output | `/pt-br/pdf-to-word` for supported PDFs | State layout limitations and English-only OCR; do not imply Portuguese scan recognition |
| imagem / foto / JPG para PDF | Image picker and page-layout controls | `/pt-br/jpg-para-pdf` core | Correct accepted formats, page sizes, margins and file-size limits |
| PNG para PDF | Dedicated PNG conversion page | `/pt-br/png-para-pdf`, reusing the image engine | Specific transparency/screenshot guidance and real PNG output support |
| editar currículo PDF | Editing task demand in BR rows; existing English résumé task provides an established equivalent | `/pt-br/editar-curriculo-pdf` | Edit a real PDF, verify saved text and explain font/layout limits; no ATS or résumé-generation promise |
| PDF/A / PDF→XML / exact KB targets | Format- or acceptance-specific intent that can require stricter output validation | Core copy must describe actual output; unsupported guarantees stay held | Metadata-only PDF/A preparation is not standards certification; generic XML is not a fiscal invoice schema; compression is not an exact-size guarantee |

Primary examples: [iLovePDF merge in Portuguese](https://www.ilovepdf.com/pt/juntar_pdf), [Adobe merge](https://www.adobe.com/br/acrobat/online/merge-pdf.html), [Adobe PNG conversion](https://www.adobe.com/br/acrobat/online/png-to-pdf.html), [Adobe image conversion](https://www.adobe.com/br/acrobat/online/image-to-pdf.html), [Microsoft PDF/Word guidance](https://www.microsoft.com/pt-br/microsoft-365/word/convert-pdf-to-word), and [Adobe PDF-to-Word](https://www.adobe.com/br/acrobat/online/pdf-to-word.html). These support a working tool plus concise task guidance as the appropriate format. Competitor conversion/quality/privacy promises were not copied into PDFPilot.

The English BR observations strengthen `/png-to-pdf` and `/pdf-to-word-scanned` where they match existing supported intent. They do not justify another English slug. Resume/device variants and merge+compress phrases were checked against existing core, pSEO and workflow owners; Portuguese workflow/platform expansion stays held until fully localized, distinct and tested.

Before investment in the largest new capabilities, capture a real BR Google SERP with location, device, date and top URLs and manually compare the output users expect. This is especially important for ambiguous legacy DOC/PPT wording and “PDF para XML.” No claim of current rank or ranking improvement is made here.
